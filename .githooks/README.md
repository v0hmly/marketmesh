# Git hooks

Репозиторные Git hooks подключаются один раз после клонирования:

```bash
task hooks:install
```

Команда настраивает локальный `core.hooksPath=.githooks`, не изменяя содержимое `.git/hooks`. Если `core.hooksPath` уже указывает на другой каталог, установка завершается ошибкой, чтобы не отключить существующие hooks незаметно.

`pre-commit` запускает `task verify` из корня текущего worktree и блокирует коммит при любой неуспешной проверке. Обход через `git commit --no-verify` допустим только как явно согласованное исключение из процесса.

Дополнительно `pre-commit` блокирует коммит при непустом WAL базы Taskboard (`.taskboard/taskboard.db-wal`): изменения задач в WAL невидимы для git, а checkout или pull подменяет основной `.db` под существующим WAL и необратимо повреждает базу. Перед коммитом базы нужно остановить процессы Taskboard (web UI, MCP) и выполнить `task taskboard:checkpoint` — он фиксирует WAL в основном `.db` и проверяет целостность.

`post-checkout` не блокирует, но предупреждает, если ветка переключается при непустом WAL — это сигнал сначала выполнить checkpoint и закоммитить базу.

Общая логика проверки WAL находится в `tools/taskboard-wal-check.sh`.
