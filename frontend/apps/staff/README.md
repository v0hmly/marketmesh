# Портал сотрудников

Самостоятельное приложение с собственными SSO, маршрутами, сборкой и origin.
Покупательские Auth/User bootstrap и аналитика storefront не подключаются.
Решение и границы — [ADR-0016](../../../docs/adr/0016-frontend-application-boundaries.md).

Из корня репозитория:

```sh
pnpm --dir frontend install --frozen-lockfile
task staff:build
task staff:verify
task dev:up -- staff
task staff:invite -- employee@marketmesh.test support
task staff:browser
task staff:perimeter
```

Staff: `https://staff.localhost:18444`, локальный тестовый IdP:
`https://oidc.localhost:18445`. Импортируйте только публичный
`.cache/dev-stack/staff/ca.crt` в доверенные CA браузера, а
`.cache/dev-stack/staff/browser.p12` — в личные сертификаты (пустой пароль).
При запросе сертификата выберите MarketMesh local corporate access. Это локальный
пропуск mTLS; без него браузер не получит даже HTML портала. На macOS можно открыть
оба файла через Связку ключей; доверие меняйте только для локального CA.
Сертификаты живут 7 дней и обновляются через `task dev:up`; после обновления
импорт повторяется. Ключ `ca.key` импортировать нельзя. Пароли тестовых `employee@marketmesh.test`
и `other@marketmesh.test` находятся в `.cache/dev-stack/staff/credentials.json`
(`employee_password`, `other_password`). Они создаются локально и сохраняются
при повторном `up`. `staff:invite` печатает новую одноразовую ссылку на 24 часа;
разрешены только эти две тестовые почты и роли `support`, `moderator`, `admin`.
Ссылка сама по себе не даёт доступ: сервер требует подтверждённую OIDC-почту.

Ссылка с `#token` сохраняется сервером на время SSO, после callback возвращает
пользователя к подтверждению приглашения. Старый формат `?token` читается для
совместимости; новые ссылки не помещают токен в HTTP URL. Переход на другое
приглашение обновляет состояние и отбрасывает ответ предыдущего запроса.

`task staff:browser` запускает Chromium с локальными CA, проверкой TLS и настоящими
OIDC/Staff/PG: SSO, повторный вход и отзыв прежней сессии, приглашение, неправильная
почта, истёкшая ссылка, завершённая сессия, cookies и отказ через публичный origin.
Пароли/cookies/ссылки не выводятся в отчёт. Тестовый браузер не получает ключ CA,
OIDC client secret или пароль БД; получает только локальный clientAuth-пропуск. Контрактные UI-тесты с подменой ответов:
`pnpm --dir frontend --filter @marketmesh/staff test:browser`.

Порты опубликованы только на loopback хоста. Staff требует clientAuth-сертификат
доверенного корпоративного CA до HTTP; подставленные заголовки, cookie покупателя
и доступ по IP/через `host.docker.internal` не заменяют пропуск. OrbStack маскирует
IP между bridge, поэтому проверка peer subnet сама по себе недостаточна.
`task staff:perimeter` проверяет оба пути из публичной сети с правильным серверным CA.
`staff-storage` соединяет сервис с существующим PostgreSQL. В корпоративном
развёртывании нужны собственные выдача mTLS и ingress с VPN/ACL. Локальный стенд
не является развёрнутым VPN; тестовый IdP не предназначен для production.

Сервис хранит host-only `__Host-mm-staff-session` (Secure, HttpOnly, Strict):
30 минут бездействия, максимум 8 часов. Возвращение во вкладку перепроверяет сессию;
межвкладочный сигнал очищает экран, запоздалые ответы игнорируются. Неопределённый
исход выхода не возвращает старые персональные данные. Экран показывает только
подтверждённый рабочий аккаунт; бизнес-функции модерации/поддержки остаются MM-59.
