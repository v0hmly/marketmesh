# ADR-0010: Композиция и поставка микрофронтендов

- Статус: Отложено
- Дата: 2026-08-31
- Авторы: команда проекта
- Заменяет: нет
- Заменено решением: нет

## Контекст

Клиентская часть будет написана на Vue и в перспективе разделена по продуктовым областям. Однако на первом этапе есть одна команда, только сервисы аутентификации и пользователей и ещё нет независимых циклов поставки UI.

Runtime-композиция микрофронтендов добавляет версионирование общих зависимостей, обработку частичных отказов, согласование маршрутизации, безопасность загрузки удалённого кода и сложность локальной разработки. Без реальной организационной границы эта цена преждевременна.

## Отложенное решение

До появления как минимум двух областей UI с независимыми владельцами или циклами поставки использовать модульное Vue-приложение в монорепозитории.

Уже сейчас соблюдать будущие границы:

- модули группируются по продуктовым областям, а не по типам файлов;
- оболочка владеет запуском, маршрутизацией верхнего уровня, обработкой сессии, темой и общими ошибками;
- продуктовый модуль не читает внутреннее состояние другого модуля;
- общий глобальный store не используется для доменных данных;
- общий пакет UI содержит визуальные примитивы, но не бизнес-правила;
- контракты API генерируются из protobuf и версионируются;
- модуль можно собрать и проверить изолированно;
- внешние токены не передаются JavaScript-модулям и не хранятся в Web Storage.

Когда критерий будет достигнут, отдельным ADR выбрать между сборочной композицией, runtime Module Federation, независимыми приложениями по маршрутам или сохранением модульного монолита. Текущий документ не утверждает Nuxt, Vite, конкретный механизм federation или обязательную независимую поставку.

## Рассмотренные альтернативы

### Runtime-микрофронтенды с первого дня

Дают независимую поставку, но увеличивают сложность и поверхность атаки до появления организационной необходимости.

### Независимые приложения по маршрутам

Обеспечивают сильную изоляцию, но усложняют общий UX, навигацию, загрузку и повторное использование оболочки.

### Пакеты времени сборки

Проще runtime-композиции и хорошо подходят монорепозиторию, но вся оболочка всё равно поставляется совместно.

### Постоянный монолитный frontend без границ

Самый быстрый старт, но доменные зависимости быстро переплетаются и делают последующее разделение дорогим.

## Последствия

### Положительные

- Начальная команда не платит эксплуатационную цену независимого runtime.
- Доменные границы можно проверить до выбора технологии композиции.
- Решение будет принято по реальным требованиям поставки и измерениям.
- Vue остаётся выбранной основой без преждевременной фиксации метафреймворка.

### Отрицательные и риски

- На первом этапе нет независимой поставки frontend-областей.
- Границы модулей требуют дисциплины и автоматических проверок импортов.
- Поздняя миграция всё равно потребует работы с маршрутизацией, состоянием и дизайном.
- Слишком мягкий критерий может бесконечно откладывать решение.

## Защитные и эксплуатационные требования

- CSP и список источников скриптов запрещают неподконтрольный удалённый код.
- Оболочка централизует обработку истечения сессии, но не раскрывает cookie JavaScript.
- Общие зависимости имеют одну контролируемую версию до отдельного решения.
- Каждый модуль имеет владельца, границу импортов и контракт событий UI.
- Ошибка одного будущего удалённого модуля не должна ломать вход и основную навигацию.

## Проверяемые инварианты

- Запрещённый импорт между продуктовыми модулями ломает проверку CI.
- Доменное состояние не помещается в общий store.
- Сгенерированный клиент не позволяет вызвать непубличный gRPC-метод.
- Cookie сессии недоступен JavaScript.
- Модуль имеет изолированный набор компонентных и контрактных тестов.

## Условие возвращения к решению

Новый ADR создаётся, когда выполняется хотя бы одно условие:

- две области UI должны выпускаться независимо;
- разные команды владеют оболочкой и продуктовым модулем;
- совместная сборка или выпуск стал измеримым ограничением;
- требуется изоляция отказа или технологии отдельной области.
