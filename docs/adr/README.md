# Журнал архитектурных решений

ADR фиксирует одно значимое архитектурное решение: контекст, выбранный вариант, рассмотренные альтернативы и последствия. Такой документ объясняет причины решения, а не только итоговую схему.

## Статусы

- Предложено — решение обсуждается и ещё не ограничивает реализацию.
- Принято — решение обязательно для новых изменений.
- Отклонено — вариант рассмотрен и не выбран.
- Отложено — решение намеренно перенесено до появления необходимых данных.
- Заменено — действует более новый ADR, указанный в документе.

Принятый ADR не переписывается так, чтобы исчезли первоначальные причины. Существенное изменение оформляется новым ADR, который заменяет предыдущий. Исправление опечаток и добавление ссылок допустимы без нового решения.

## Как добавить решение

1. Скопировать [шаблон](template.md).
2. Выбрать следующий последовательный номер и короткое имя файла.
3. Описать контекст без привязки к уже выбранному ответу.
4. Зафиксировать решение в проверяемой форме.
5. Перечислить реальные альтернативы и причины отказа.
6. Указать положительные и отрицательные последствия, эксплуатационные и защитные ограничения.
7. Добавить документ в реестр.
