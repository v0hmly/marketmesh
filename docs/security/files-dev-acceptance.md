# Ограниченная приёмка MM-43 для dev

Статус: **предложено, ожидает явного подтверждения владельца** в
[PR #91](https://github.com/v0hmly/marketmesh/pull/91). Сам документ, зелёный CI,
создание последующих задач или команда «довести до слияния» не являются принятием
остаточного риска. До подтверждения сохраняются исходные блокеры слияния.

Владелец решения и остаточных рисков — `v0hmly`. Предлагаемый срок действия
исключения — до **22.10.2026**, без автоматического продления. Решение применяется
только после явного согласования этого документа владельцем.

## Принимаемый результат

Предлагается принять MM-43 как реализацию приватного файлового контура,
проверенную локально и подготовленную к дальнейшей эксплуатационной проверке.
После подтверждения владельца, актуального независимого одобрения и успешного
обязательного CI допускаются squash merge PR #91 в `dev`, принятие
[ADR-0015](../adr/0015-private-file-data-plane.md) в указанной области и перевод
MM-43 в `done` отдельным PR с фиксацией решения. MM-43 закрывается только после
слияния и успешной проверки интеграционной ветки.

Это явное изменение области приёмки MM-43: непройденные исходные критерии
контейнерной безопасности и полного отказа DC сохраняются в MM-88/MM-89 как
обязательные условия включения сервиса. Они не объявляются выполненными.
Для изменения статуса ADR и MM-43 основанием служит опубликованное подтверждение
владельца; до него ADR остаётся предложенным, MM-43 — `in_progress`.

## Границы исключения

- В обычных окружениях `FILES_BROWSER_ENABLED=false` на обоих gateways,
  `AUTH_FILES_SCOPED_ENABLED=false`, `Control.Enabled=false`. Их значения по
  умолчанию уже выключены; этот PR их не меняет.
- Разрешена интеграция исходного кода. Эксплуатационный запуск Files, включение
  публичного API, обработка реальных пользовательских файлов и публикация
  контейнеров этим решением не разрешаются, в том числе в dev.
- Локальные проверки допустимы только на собственном одноразовом стенде
  OrbStack с синтетическими fixtures, тестовыми credentials и закрытыми
  loopback endpoints. Там флаги временно включает сам тестовый harness.
- Workflow `CI/verify` выполняет проверки с read-only token; он не публикует
  образы и не развёртывает Files. Обязательный CI, независимое ревью и запрет
  прямого push в `dev` сохраняются.
- После 22.10.2026 необходима повторная оценка владельца. Истечение срока не
  включает API автоматически и не превращает открытые условия в выполненные.
  Уже слитый отключённый код можно сохранять; новое решение требуется для
  дальнейшего использования исключения.

## Основания и остающийся риск

[Отчёт проверок](../testing/files-data-plane.md) разделяет полный локальный
прогон 21.09 и повторные проверки 22.09. Текущая реализация прошла обязательный
CI, независимое ревью пяти исправлений, Go workspace/isolated/race, frontend,
protobuf, PostgreSQL-регрессию Claim и проверки аудита/диагностики.

Trivy 0.74.0 от 22.09.2026: Files runtime — 0 findings; пересобранный sandbox —
1 Critical, 72 High, 126 Medium, 214 Low, 11 Unknown. Digest sandbox:
`sha256:11a6a51651d5c950ee7f3c6a80cdfeb6cc4f223f079b26bb9f5553f3324fe0e4`.
Остальные образы и исходные находки перечислены в отчёте. Ignore-списки не
добавлены, package metadata не удаляется для сокрытия результатов сканера.

Проверка кандидатов trixie/trixie-security 22.09 показала отсутствие обновлений
установленных libxml2, libtiff, expat, curl и util-linux. Debian отмечает
[CVE-2026-6653](https://security-tracker.debian.org/tracker/CVE-2026-6653) и
[CVE-2026-86138](https://security-tracker.debian.org/tracker/CVE-2026-86138)
в стабильной libxml2 как vulnerable. Подмена дистрибутива или ABI без повторной
проверки AV/CDR не считается исправлением. Отсутствие доступного stable-патча
тоже не означает отсутствия риска: parser остаётся поверхностью атаки.

Пользователь подтвердил 22.09 наличие только локального OrbStack. Текущий
Compose проверяет отдельные отказы процессов, delivery и синхронной реплики,
но не весь отказ DC. Четырёх-VM topology ADR-0014 сама по себе не выполняет
Files-сценарий. Ограничения общей физической машины должны оставаться явными;
нельзя выдавать локальный результат за испытание независимых физических DC.

## Отзыв и откат

Если границы нарушены, немедленно выключить оба browser-флага и Auth Files
listener, остановить Files control/worker; дождаться TTL ранее выданных URL
(до 60 с). Сохранить DB, buckets, volumes и KMS keys. Исправление конфигурации
либо revert кода выполняется отдельным PR; down-миграция для удаления реальных
метаданных не применяется. До нового согласованного решения приём файлов
остаётся выключенным.
