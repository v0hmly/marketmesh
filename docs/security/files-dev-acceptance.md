# Приёмка MM-43 в текущем dev

Владелец — `v0hmly`. Решение от **22.09.2026**, пересмотр остаточных CVE до
**22.10.2026**. Владелец подтвердил, что сейчас есть только dev и локальный
OrbStack: интеграция кода не должна зависеть от обязательного выключения Files;
доступные сейчас контейнерные CVE принимаются для dev, а полный локальный DC E2E
нужно выполнить до завершения MM-43. Это заменяет прежнее предложение принять
только отключённый код и отложить DC E2E.

## Область решения

После актуального независимого ревью и успешных обязательных проверок допускается
squash merge [PR #91](https://github.com/v0hmly/marketmesh/pull/91) в `dev`.
[ADR-0015](../adr/0015-private-file-data-plane.md) принимается для этой области.
MM-43 переводится в `done` только после слияния и успешного CI интеграционной ветки.

Обязательное выключение Files не является условием приёмки. Существующие флаги
остаются параметрами конфигурации: запуск требует настроенных Auth audience,
scoped mTLS, приватных S3/KMS и БД. Решение не включает отсутствующее окружение
автоматически и не ослабляет проверку владельца, сессии или содержимого файла.

GitHub CI остаётся одним обычным `verify` job с read-only token. Он не публикует
контейнеры и не запускает четыре VM. Полный [DC E2E](../testing/files-dc-e2e.md)
выполняется на OrbStack, его результат проверяется перед merge. Короткие
отрицательные проверки безопасности harness выполняются без VM.

## Остаточный риск CVE

В MM-88 сохраняются исправления образов Files, AV/CDR, SeaweedFS и OpenBao;
общие PostgreSQL/account образы остаются в существующей MM-67. Открытые CVE
не объявляются устранёнными и не скрываются ignore-списками или удалением
package metadata. Исключение относится к текущему dev; для будущего окружения
и использования после 22.10.2026 нужна повторная оценка владельца.

[Отчёт сканирования](../testing/files-data-plane.md) сохраняет исходные findings.
Trivy 0.74.0 от 22.09: Files runtime — 0; sandbox — 1 Critical, 72 High,
126 Medium, 214 Low, 11 Unknown. Проверенный sandbox digest:
`sha256:d6ffb94795adcbfa5978c7a59ae34301891c93c9c47ebf09aa0ba88cf1a24cf6`.
Проверенный Trivy/CRI config ID:
`sha256:9a4a985d8d2ed8f97d66f93e5af51890a8a03394718521a2536af41868e73ec4`.
[Сводка и SHA-256 исходных отчётов](../testing/evidence/mm43-container-scan-2026-09-22.json)
связывают findings с образами успешного DC E2E.

В trixie/trixie-security на эту дату нет обновлений установленных libxml2,
libtiff, expat, curl и util-linux. Debian отмечает
[CVE-2026-6653](https://security-tracker.debian.org/tracker/CVE-2026-6653) и
[CVE-2026-86138](https://security-tracker.debian.org/tracker/CVE-2026-86138)
в стабильной libxml2 как vulnerable. Отсутствие stable-патча не устраняет риск:
парсер обрабатывает недоверенные байты. Ограничения форматов, AV/CDR,
изоляция, лимиты и одноразовый sandbox сохраняются.

## Что доказывает локальная проверка DC

Полностью останавливаются обе VM выбранного логического DC, затем проверяются
fencing, promotion, сохранность подтверждённых метаданных и READY-копии,
проверка Auth/owner/session, ожидание `remote_apply` и восстановление загрузки.
Сценарий повторяется для второго DC. Диски VM сохраняются; один физический Mac
не доказывает независимость питания, сети или необратимую потерю дисков DC.

Quarantine, internal-clean и worker расположены в DC A. Загрузка продолжается
после восстановления нужного DC; новые записи не подтверждаются без меж-DC
синхронной реплики. Проверка будущих физических fault domains при появлении
такого окружения остаётся в MM-89 и не блокирует текущую приёмку dev.

## Откат и пересмотр

При инциденте остановить приём Files, выключить browser-маршруты и scoped Auth
listener, дождаться TTL выданных URL (до 60 с). Сохранить БД, buckets, аудит
и KMS keys. Изменение конфигурации или revert выполняется через PR; удаление
реальных метаданных down-миграцией не является планом отката.
