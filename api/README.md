# API

Каталог содержит исходные protobuf-схемы и воспроизводимо сгенерированные клиенты и серверные типы. Исходные схемы отделяют публичные ConnectRPC-контракты от внутренних gRPC-контрактов и протокола обратного туннеля.

Сгенерированные файлы не редактируются вручную.

## Инструменты и команды

Единственная конфигурация protobuf workflow находится в корневом `easyp.yaml`. EasyP запускает только локальные плагины: схемы не отправляются в публичный сервис генерации. Точные версии CLI, `protoc` и плагинов зафиксированы в `tools/protobuf-versions.env`; скачанные бинарные файлы и кэш зависимостей хранятся в игнорируемом `.cache/protobuf`.

```bash
task api:bootstrap       # установить зафиксированные инструменты
task api:deps            # скачать зависимости по easyp.lock
task api:lint            # проверить схемы
task api:generate        # обновить Go и TypeScript код
task api:breaking        # сравнить v1-контракты с dev
task api:generate-check  # сравнить чистую генерацию с репозиторием
task api:self-test       # проверить плагины и отрицательные сценарии
task api:verify          # выполнить все API-проверки
```

`task api:deps:update` используется только при осознанном изменении зависимости в `easyp.yaml`; изменившийся `easyp.lock` должен входить в тот же pull request. EasyP 0.16.1 разрешает breaking reference только как локальную ветку, поэтому перед проверкой локальная `dev` должна быть обновлена из `origin/dev`.

`task api:self-test` создаёт временный v1-контракт вне дерева исходников и подтверждает, что повторная генерация совпадает побайтово, некорректное имя поля отклоняется lint, а удаление поля обнаруживается breaking check.
