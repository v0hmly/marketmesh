# Инструменты репозитория

Каталог содержит локальную и CI-автоматизацию. Скрипт `go-workspace.sh` запускает одинаковые Go-проверки во всех модулях и проверяет разрешённый граф зависимостей. Taskfile является единым интерфейсом к этому скрипту и не содержит собственного списка модулей.

## Проверка совместимости protobuf

`task api:breaking` сравнивает все текущие `.proto` в `api/proto`, включая
незакоммиченные и новые файлы, с деревом `dev`. Для другого baseline задайте
`PROTO_BREAKING_REF`, например `PROTO_BREAKING_REF=origin/dev task api:breaking`.
Скрипт выводит разрешённый SHA; отсутствующая ссылка завершает проверку ошибкой,
без подстановки другой ветки.

В EasyP 0.16.1 breaking разрешает локальные imports от корня Git, а `--path`
не меняет этот корень. Поэтому `tools/protobuf.sh` создаёт временный репозиторий
в `.cache/protobuf`: экспортирует `api/proto` выбранного commit в его корень,
фиксирует baseline и заменяет схемы текущими файлами. Состав и относительные
пути схем обеих сторон сохраняются. Используются текущие `easyp.yaml`,
`easyp.lock` и прежняя закреплённая версия EasyP; в временной конфигурации
меняется только ссылка baseline. Это также обходит приоритет YAML-ссылки над
CLI `--against` в этой версии EasyP.

Hooks и подпись временных commit отключены; рабочее дерево, index и история
основного репозитория не меняются. Временный каталог удаляется и при ошибке.
Проверка относится к схемам; исторические версии внешних зависимостей отдельно
не сравниваются — обе стороны используют текущий lock-файл.

`task api:self-test` проверяет воспроизводимость генерации, отклонение ошибки
lint, успешное сравнение схем с локальными импортами, включая новый untracked
import, и конкретное сообщение `BREAKING_CHECK` об удалённом поле. Ошибка
разрешения import сама по себе больше не считается доказательством работы
breaking detector.
