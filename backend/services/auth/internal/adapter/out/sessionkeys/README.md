# Ключи внутренних session assertions

`New(Config)` загружает локальный секретный файл и проверяет расписание. `Path`
абсолютный, `Issuer` и `Audiences` задаются сервером. `MaxTTL` не меньше секунды;
`Clock` по умолчанию `time.Now`. Audience выбирает только заранее заданный набор
scopes; произвольные клиентские scopes не принимаются.

Формат файла (не более 64 KiB, не более 64 ключей):

```json
{
  "keys": [
    {
      "kid": "auth-2026-09",
      "private_key": "BASE64URL_64_BYTE_ED25519_PRIVATE_KEY_WITHOUT_PADDING",
      "public_key": "BASE64URL_32_BYTE_ED25519_PUBLIC_KEY_WITHOUT_PADDING",
      "sign_from": "2026-09-01T00:00:00Z",
      "sign_until": "2026-10-01T00:00:00Z",
      "verify_until": "2026-10-01T00:05:00Z"
    }
  ]
}
```

Оба ключа используют строго `base64.RawURLEncoding`, без padding. Закрытый ключ —
64 байта Ed25519 (seed + public), соответствие public/seed проверяется. Для уже
завершившего подпись ключа `private_key` можно удалить; public и расписание нужно
сохранить до `verify_until`. Файл хранится как секрет Auth, не в git; рекомендуемые
права файла — `0600`.

Окно подписи `[sign_from, sign_until)`. Окна разных ключей не пересекаются, и
на текущий момент должен существовать ровно один активный signer. Новый public
key публикуется заранее. `verify_until >= sign_until + MaxTTL`; при использовании
verifier с ненулевым leeway оператор добавляет также leeway к периоду публикации.
В точности на `verify_until` ключ исключается из публикации и доверия.

Для ротации подготовьте полный файл рядом и замените его атомарным rename.
`Issue`, `PublicKeys`, `Key` перечитывают и валидируют каждый снимок. Некорректный,
недоступный или неполный снимок вызывает отказ, старый снимок не используется.
В пределах жизни процесса запрещены замена материала существующего kid,
сокращение verify_until и удаление ещё доверенного ключа. Истёкший ключ можно убрать,
но его kid нельзя повторно использовать с другим материалом даже после удаления.
Эта защита истории не переживает рестарт: уникальные kid и корректный rollout
секретов остаются обязанностью оператора.

`PublicKeys()` возвращает только JWK `kty=OKP`, `crv=Ed25519`, `alg=EdDSA`,
`use=sig`, `kid`, `x` и `verify_until`. `Key(kid)` возвращает копию public key и bool;
`KeySource()` адаптирует его к `sessionassert.KeySource`. Неизвестный или
просроченный kid и ошибочный снимок не дают доверенного ключа.

`Issue(ctx, record, audience, expiresAt)` принимает абсолютный срок с точностью
до целой Unix-секунды. После чтения файла по свежим часам проверяются активность
canonical record, access expiry, audience и остаток жизни assertion. Deadline
не может превышать AccessExpiresAt, ExpiresAt или now+MaxTTL; молчаливое сокращение
не допускается. Подписанный exp точно совпадает с переданным expiresAt и сроком
в ответе application. Истёкший срок, дробные секунды и отсутствие хотя бы одной
сериализуемой секунды приводят к отказу. Application проверяет access token/Redis
и выбирает ограниченный абсолютный срок до вызова порта.
Сам адаптер не делает SQL/Redis-запросы. В ошибки не включаются путь, содержимое
файла, private key или токен; ошибки конфигурации/снимка дают `ErrUnavailable`,
невалидная сессия/audience/TTL — `ErrInvalidSession`.
